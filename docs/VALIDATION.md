# 验证范围

记录更新：2026-10-22。VPN 并存的实际反馈来自 2026-10-20；测试不附带任何真实配置、网络快照、认证日志或密码记录。

## 已验证

- 在 Apple Silicon / macOS 26.5 / Rosetta 上，针对指定 x86_64 构建生成、安装并启动副本，三个角色进程正常出现。
- RPC 冷启动修订后可打开副本；修正重连时间并恢复索引后，配置重读和正常重启不再清空会话，用户完成登录。
- 已保存网关及厂商登录记录在本机私有临时目录中复制一致，保留副本身份，关闭自动登录，原版源文件未被写入；没有解密密码。
- 用户反馈两个需要短信验证码的网关在增加物理出口回退路由后同时保持在线至少 2 分钟。
- 初版保护遗漏第三个网关时，第三条在 SSL 建连阶段超时；将保护扩展至全部已保存网关后，用户确认三个 VPN 同时保持在线至少 2 分钟。
- 本机四个已保存公网 IPv4 网关的回退保护均已核对存在，并使用物理网卡。**这不等于四条已同时登录。**

## 自动测试

```sh
python3 -m unittest discover -s tests -v
```

测试覆盖固定构建拒绝条件、补丁字节和端口隔离、链接及完整性检查、配置重连值与索引恢复、启动选择与锁、安装失败不启动、凭据记录继承与回滚、路由计划与出口判断、只补缺失路由、撤销标记及部分失败恢复。

本机带受支持原版及已生成副本时共 60 项测试通过。其中 18 项新增测试覆盖模拟的不同版本和不同偏移、完整构建匹配、未知版本和架构拒绝、规则歧义、旧记录兼容、错误构建不复用，以及拒绝发生在 sudo / 配置 / 路由操作之前。模拟版本不代表新增真实客户端支持。

无厂商 App 的干净环境会跳过真实源文件与生成副本检查，其他测试使用临时文件或模拟数据。它们不启动客户端、不认证、不修改系统路由。GitHub Actions 仅验证源码和这些离线行为，不能证明 VPN 业务可用。

Manifest 的 `validation` 字段描述该文件产物的离线校验范围，实际连接结果不写回该字段。

## 业务验收步骤

先确认每条 VPN 单独连接可用，再验证并发。选择各网关管理员认可的已知内网 IP、域名及实际业务作为测试目标。

1. 未连接 VPN 时保存基线：`python3 network_snapshot.py build/snapshots/before`。
2. 仅连接 A，确认已知内网 IP、域名和业务正常，保存 `build/snapshots/a`。
3. 连接 B，确认 A 仍在线，两边分别测试相同目标，保存 `build/snapshots/ab`。
4. 使用 `route -n get <目标IP>` 比较目标出口及快照中的 DNS/代理，不根据最大的 utun 编号猜测归属。
5. 逐条增加 C、D，每次都复测已连接网关的业务，并观察至少 2 分钟；更长的稳定性测试另行记录。
6. 正常断开其中一条，复测其他连接的 IP、DNS 和业务；交换连接顺序再次验证。

只有各客户端在线、各自真实业务正常、断开单条后其余业务仍正常，才算完成该组合的业务验收。

快照仅在本地保存，但包含网络地址、路由、DNS、代理和进程路径。不要直接提交快照或完整日志；反馈时仅提供必要且已脱敏的片段，不包含网关标识、账号、保存的登录记录或验证码。
