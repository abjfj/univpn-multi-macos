# 多版本识别与适配

工具会自动识别本机客户端并选择已审核规则。它不根据“看起来相似”的版本套用补丁，也不把未知构建标记为兼容。

## 当前支持列表

运行下列命令可查看随当前源码提供的真实规则：

```sh
python3 univpn_multi.py profiles
```

目前内置一份真实规则：

| 规则 ID | 版本 | 架构 |
|---|---|---|
| `univpn-10781.19.0.1214-x86_64-r1` | `10781.19.0.1214` | x86_64 |

具体哈希见[分析记录](ANALYSIS.md#兼容性门槛)。规则集合和补丁引擎支持多个经过审核的构建，但尚无第二个真实客户端样本的验证结果；测试里的模拟版本不属于支持范围。

## 自动检测流程

1. 只读解析 App 的 Info.plist，识别版本号及 Bundle 身份。
2. 只读检查 UI、提权服务和连接后台的布局、Mach-O 架构与 SHA256。路径含链接、组件缺失或不可读时拒绝。
3. 将三个核心文件作为整体匹配规则，要求版本、架构、全部哈希和 Bundle 身份一致，不从不同规则拼凑组件。
4. 在内存中检查该规则的身份字符串数量、每个补丁的原始字节和等长修改要求。恰好一份规则全部通过才允许生成副本。

每份规则包含独立的版本列表、哈希、字符串数量、补丁偏移、前置字节及端口/固定字节替换。新版本可使用不同偏移，不需要修改构建引擎中的版本分支。当前引擎处理 x86_64 和现有三组件布局；其他架构或服务模型需先实现对应引擎，不能只添一个版本号。

只读检查默认安装或指定 App：

```sh
python3 univpn_multi.py inspect
python3 univpn_multi.py inspect --source /path/to/UniVPN.app
```

报告字段：

| 字段 | 含义 |
|---|---|
| `version` / `bundle_version` | 客户端自行声明的版本信息 |
| `architecture` | x86_64、arm64、universal、mixed 或 unknown |
| `supported` | 当前工具是否有唯一且通过全部前置检查的规则 |
| `profile` | 匹配的规则 ID；未通过时为 null |
| `reason` | 通过或拒绝的原因 |
| `sha256` / `binaries` | 三个核心文件的哈希、架构或读取错误 |

无匹配项或检查失败时，报告返回 `supported: false`，进程退出码为 1。App 路径无效或 Info.plist 损坏时，会直接给出错误并返回非零状态。报告仅检查程序元数据和三个可执行文件，不读取网关、账号、密码记录或日志。

## 不兼容时的行为

- 未适配版本：提示版本和架构，保留只读报告供后续分析。
- 同版本不同哈希：提示可能是不同构建或混合组件，不沿用旧偏移。
- ARM、Universal 或不一致架构：拒绝套用 x86_64 补丁。
- 多份规则同时匹配、原始字节不符或身份不符：停止，不猜测。
- `build` / `vpn-new`：先做识别；失败时不生成副本、不安装、不同步配置、不调用 sudo、不修改路由、不启动窗口。`--dry-run` 同样检查兼容性。

不提供 `--force`、忽略 SHA 或仅凭端口常量扫描后直接修改的路径。`profiles` 和 `inspect` 不修改客户端；已有副本可以通过自身记录校验，原版升级后不会自动覆盖旧副本。`vpn-new` 不复用其他来源构建的副本，也不会安装来自其他规则的已有生成目录。

新副本的 Manifest 保存实际版本、架构及 `source_profile`。以前生成的副本没有这两个新增字段时，通过其已有版本和源哈希推断规则，仍能校验和使用；如果无法唯一推断则拒绝。旧版修复还要求当前原版与目标副本来自同一构建。

## 接入另一个真实版本

1. 在具备使用许可的本地机器取得客户端，运行 `inspect` 收集不含账号配置的元数据；不要提交 App、安装包或个人配置。
2. 分析三个核心文件，确认身份隔离、端口、单实例、权限、启动、配置与升级机制；不能因为常量或版本号相近就复用旧规则。
3. 在 `univpn_profiles.py` 添加独立 BuildProfile，登记版本、架构、全文件哈希和带前置字节校验的补丁。仅修改版本号或哈希不是完整适配。
4. 添加选择正确规则、错误哈希拒绝、指令字节校验及生成记录的测试，确认不会改变旧构建输出。不同架构、配置格式或服务布局还需专门实现。
5. 在本地验证生成、安装、启动、认证和多个连接并存，再按[业务验收步骤](VALIDATION.md#业务验收步骤)检查业务、DNS 和断线影响。记录结果与限制后才更新真实支持列表。

工具不会自动下载客户端或远程补丁规则；新增规则随经过审查的源码更新提供。
